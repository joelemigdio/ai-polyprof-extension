# PolyProf 0.4.0 (alpha)

**Released:** 2026-11-16
**Supported pages:** The extension popup, and Cal Poly Student Center / Schedule Builder at `https://cmsweb.pscs.calpoly.edu/psc/*`.
**Data source:** Real PolyRatings data on the in-page hover card. The popup still renders invented demonstration data.

## Summary

Six additions. Professor detail views now carry a **review summary** — recurring themes, strengths, and concerns counted from the professor's own review text, rather than a restatement of your preferences. Classes can be **favorited** from either surface and reviewed in one list. Recommendations now disclose the cohort, rating, sample size and confidence behind them. The professor comparison works on real pages for the first time. And the hover card is now genuinely operable from the keyboard instead of only looking that way to a screen reader.

## What's new

- **Review summary on both surfaces.** Opening a professor shows what reviewers keep bringing up, split into strengths and concerns, with the number of reviews each theme was counted in. It states when the evidence is thin and says plainly that no AI model produced it.
- **Favorited classes.** Star a class in popup search, or use **Save this class** on a portal hover card. The header star opens the list, shows a count badge, and each entry can be removed. Favorites persist in `chrome.storage.local` and the two surfaces stay in sync while both are open.
- **The hover card is keyboard-reachable.** Previously `Tab` opened the card but focus stayed on the row, and the blur handler actively prevented tabbing in — so nothing inside the `role="dialog"` could be reached. `Tab` from a focused row now moves into the card, the card stays open while focus is inside it, and `Esc` closes it and returns focus to the row.
- **Visible failure state.** If PolyRatings is unreachable, a dismissible notice says so. Previously the error went to diagnostics, which are compiled out of shipped builds, so a failed load looked identical to the extension not running.
- **Preference priority.** Selected learning styles can now be ranked. The Preferences screen lists them most-important-first with their weight, and ↑/↓ reorder them. Weights decay linearly across the ranking — three styles split 50/33/17 — so reordering visibly changes match percentages, professor ordering, fit lines, and the recommendation copy, which now names which numbered priority a professor actually satisfied.
- **Recommendation explanations now disclose their evidence.** Every recommendation names the cohort it used, that cohort's rating, the sample size, a confidence band, and the preferences applied. Class standing is a new **optional** preference; reviews are grouped by the reviewer's academic year with a fallback ladder (your year → nearby years → everyone) and a minimum cohort size of 3, so a mean never describes one identifiable student. The tier used is always stated, so a widened group is never passed off as a peer match.
- **Professor comparison works on real data.** `buildCourseProfessorComparisons` previously nulled every field unless the document was a test fixture, so on a real Student Center page the Compare view showed "Unavailable" for every column. It now resolves real PolyRatings records. The columns were also restructured onto what PolyRatings actually measures — overall, presents material clearly, recognizes student difficulties, review count, tags — because the old Workload/Difficulty/Flexibility columns had no backing field, and `studentDifficulties` means "recognizes student difficulties" (higher is better), so showing it as "difficulty" would have inverted its meaning.
- **Compare is enabled in the popup**, with side-by-side bars and the leader marked per metric. It was previously a dead, disabled button.
- **Clear all my data.** The Preferences screen can now erase saved preferences, class standing, and favorited classes. `resetPreferences` and `clearFavorites` already existed but had no caller, so the spec's deletion requirement had no UI path.
- **Toolbar icons.** The extension no longer shows Chrome's grey puzzle piece.

## Changed

- `host_permissions` dropped the redundant `cmsweb.pscs.calpoly.edu` entry; the content-script match already grants that origin and nothing fetches it.
- Hover-card rating pills darkened from `#b4801f` to `#8a5f10` — the old value was 3.1:1 on the cream pill, below the 4.5:1 bar, on the most load-bearing number on the card. Popup colours are untouched, since those match the Figma handoff.
- Review ratings in the popup detail view were labelled "out of 5" while the data is on PolyRatings' 0–4 scale.
- **Removed** the vestigial `useMockData` gate from the integration; it survived from the demo-data era and was what suppressed real comparison data.
- **Fixed:** Shopping Cart rows never resolved a course code. The adapter overrode the section element to the cart row without recomputing the code from it, so course-scoped ratings and titles silently never appeared on that surface.
- **Default learning styles changed** from `project-heavy, code-evaluation, labs` to `visual-slides, responsive, structured`. The old defaults were three of the five traits PolyRatings data cannot substantiate, so a fresh install matched nothing and reported that every professor failed every preference. Saved preferences are untouched.
- Demo review text in the popup was expanded from two to six reviews per professor so the review summary has a corpus to work on.

## How the review summary works

It counts, it does not generate. Each review is scanned for multi-word cue phrases grouped into ten topics, with separate positive and negative cues per topic and a negation window that flips a cue negated in context. A topic becomes a theme once enough distinct reviews mention it, and a strength or concern only when one polarity outweighs the other — topics reviewers disagree on stay neutral. PolyRatings' tag counts can corroborate a topic the reviews raised but never introduce one.

Measured against live PolyRatings data for twelve CSC professors with 20+ reviews each: 12/12 produced themes, 10/12 strengths, 8/12 concerns.

## How to use what is new

### Review summary

1. Open a class hover card on the portal and click a professor, **or** open the popup, pick a class, and click a professor.
2. The **Review Summary** card sits above Top Reviews. Theme chips are colour-coded — green where reviewers were positive, orange where negative, grey where they disagreed — and each carries the count of reviews it was found in.
3. A professor with few reviews gets an explicit weak-signal warning rather than a confident-looking summary.

### Favorites

1. In popup search, click the star on the right of any class card. The header star gains a count badge.
2. On the portal, open a class hover card and click **Save this class**.
3. Click the header star to see the list; click the gold star on an entry to remove it.
4. Saving in one surface updates the other immediately, with no reload.

### Preference priority

1. Open Preferences and select two or more learning styles.
2. The **Preference priority** list appears, numbered, with each style's weight.
3. Use ↑ / ↓ to reorder. The weights update immediately.
4. Go back to Search — match percentages, card ordering, and fit lines all shift. With three styles, moving one from last to first takes it from 17% to 50% of the preference signal.

### Recommendation explanation

1. Open a class in the popup. The recommendation panel names the cohort, its rating, and the sample size — e.g. "Juniors and nearby years rated John Clements 3.02 out of 4, across 6 reviews."
2. Without a class standing set it uses every reviewer and says so, prompting you to add one.
3. Set **Class standing** in Preferences and reopen — the basis changes, and a confidence badge plus a caveat explain any fallback.

### Compare

1. From a class's results, press **Compare**. Each professor shows overall, presents clearly, and recognizes struggles as bars, with ▲ marking the leader per metric.
2. On the portal, open a course card and press **Compare Professors** for the same breakdown over the instructors currently visible.

### Keyboard

1. `Tab` to a class row on the portal — the card opens.
2. `Tab` again — focus moves into the card, onto the first professor.
3. `Enter` opens that professor; `Tab` continues through the card.
4. `Esc` closes the card and returns focus to the row you started on.

## Known limitations

- **The popup still shows invented ratings for real faculty names.** Only the hover card reads PolyRatings. Do not screenshot the popup for an audience that may read the ratings as real.
- **Peer cohorts are same-year only.** Reviewer major is not in PolyRatings data at all, so the spec's same-major cohort cannot be built from this source. The UI names the group it actually used rather than implying a major match.
- **Summary matching is literal.** "Grading criteria are *unusually* clear" does not match the cue `grading criteria are clear`. Coverage is a floor, not a ceiling.
- **Class time preferences are stored but unused** in matching.
- **Favorites are local and unsynced**, keyed by course plus professor.
- **Live portal compatibility is still unverified.** See [Student Center adapter assumptions](../STUDENT_CENTER_ADAPTER_ASSUMPTIONS.md).

## Data and privacy

- Favorites and preferences live in `chrome.storage.local` on one browser. Nothing is sent anywhere and there is no account.
- The extension reads no schedule records and writes nothing back to the portal.
- The hover card shows real reviews written about real professors. Name matching requires an unambiguous match: two different people share a full name in the data, and such a tie deliberately resolves to no match rather than guessing.
